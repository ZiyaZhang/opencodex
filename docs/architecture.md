# OpenCodex 架构与边界

OpenCodex 是每位用户本地运行的 DSH 第三方插件。产品目标是把被选中的 Codex 功能转换成可审阅的 DSH 插件，并在独立环境中验证；发现新功能本身不启动昂贵的复刻任务。

## 两个入口，一份任务记录

更新线索与用户主动描述都形成候选功能。用户选择复刻后，任务依次积累调查证据、行为/视觉规格、生成产物与验证结果。用户也可以开启本地版本更新后的自动调查：该模式只整理变化与证据，完成为 `researched`，等待用户另选要复刻的功能，不直接生成或安装插件。前台操作等待用户开始；复刻完成且通过隔离验收后，Host 自动安装到当前 DSH profile 并启用。目标无法访问或 DSH 缺少扩展点时，保留已完成工作并显示具体缺口。

主动任务可附一张 PNG/JPEG/WebP 参考图，最大 2 MiB，通过文件选择或粘贴提供。Host 校验后在新任务目录写入固定名称的图片，并把相对路径附到任务描述；创建仍停在 draft，不自动启动模型。研究会话需要实际图像读取能力才能观察内容，不能把上传成功当成图像理解或目标交互已验证。

实现分成三层：纯状态/预算核心负责持久化和状态转换；DSH host adapter 负责真实 session、模型用量、工具/RPC 和安装边界；Client UI 展示候选、预算、进度、前台请求和产物。知识资源不主动执行工具，它们为研究 session 提供按需指引。

## 资源加载合同

`resources/catalog.json` 是允许读取的资源清单，格式为 `{schemaVersion:1, entries:[{id,title,kind,path,description,topics}]}`。`path` 是包根目录内的相对路径，`kind` 为 skill、reference 或 sources。Host 只按 ID 查表读取，不接受任意路径。`opencodex_read_resource({id})` 默认返回章节/来源索引、字符偏移与 SHA-256；不超过 3,000 字符的短资料同时返回全文。长资料通过 `action: read` 定点读取，默认 3,000、最多 6,000 字符，支持 nextOffset。用户界面的资料阅读仍可显示全文。入口 ID 为 `opencodex`，来源索引 ID 为 `source-index`。

`resources/sources.json` 格式为 `{schemaVersion:1, checkedAt, sources:[{id,title,url,topics,platforms,sourceType,checkedAt,notes}]}`。checkedAt 表示维护时读取了公开内容，并不表示所有用户均可使用该功能。索引不包含原始网页、私有聊天、解包代码或账号资料。

## 研究工具与可信度

`opencodex_job` 面向绑定的研究 session 提交 status/record/evidence/spec/scaffold/artifact/verification/stage/request_foreground/foreground_done/repair 等操作；以运行时 schema 为准。status 返回任务、预算和按分类分页的 dossier 摘要，record 按原 ID 分段读取完整记录，便于重启后复用证据而不把全部历史放进上下文。研究 agent 可提交检查结果，不能自行授予日常环境安装资格。Host 检查产物，独立隔离验收记录决定是否完成复刻；安装动作由 Host 自动衔接，无第二次安装确认。

scaffold 在不存在或为空的 `plugin/` 中复制固定的八个通用模板文件，替换合法包名；拒绝 symlink 和覆盖已有文件。它不安装依赖、不构建、不实现任何被研究功能。模板提供锁定的公开 SDK、空 Host/Client 贡献、浏览器 loader 和打包脚本，减少模型重复调查固定框架结构的消耗。返回值同时携带实际 Client 初始源码、模板依赖版本、文件摘要与构建命令，避免重新读取每个模板文件；模板版本不等于已探测运行环境。生成后仍需实现具体行为并提交实际 tarball。

资料中的工具名是调查线索；当前 DSH 的注册工具及 REA 的实际 tools/list 才是调用契约。静态分析确认客户端结构，CUA 确认特定场景行为，推测保留为推测。无法观察的云端实现不纳入“已还原”的结论。

## 预算与执行

预算必须在模型调用边界实施，并覆盖可追踪的子任务、失败重试和并发研究。账本区分确认用量与未结算预留。v0.1 的日累计按 UTC 日期结算；跨日未结算调用继续占用预留，结算后计入结算日。预算只是执行限制，不是精确账单保证：在途调用与缺失的 provider usage 都需要如实展示。外部模型 CLI/API 和未追踪 agent 不属于被允许的研究执行路径。

任务目录持久化断点和产物，日常 profile 与研究 workspace 分离。这种目录隔离不等同操作系统安全沙箱；运行生成代码的权限仍由 DSH/OS 提供。恢复之前核对版本、上次待执行动作与用量状态，不盲目重放有副作用的动作。

调查阶段连续四次模型尝试没有新增登记证据或规格时，Host 在下一次尝试前暂停；失败重试也计入，文件写入本身不重置此进度门限。用户显式恢复不重置 token/时间消耗。有效的同任务规格可让编写规格或开发阶段恢复原阶段；当前不自动恢复验收阶段或开始修复。恢复后的模型应直接使用既有记录和项目，而不是重新读取整套资料或再次创建脚手架。

## v0.1 当前实现范围

公开来源扫描读取官方 changelog 的 RSS，必要时回退 HTML，按具体功能生成候选；默认限最近 90 天、8 个适用发布条目、32 项功能。首次检查也解析条目，后续按功能指纹去重，保留用户已选择的状态。它筛除 CLI、移动端专属、纯模型和修复列表，解析失败与没有新增分别报告。文档不证明本机已开放。公共来源索引用于选定任务的按需研究，不等于同等数量的后台监测器。

本地监测由用户设置 `localVersionFile` 的绝对路径，默认留空。当前只读取不超过 1 MiB 的 XML `Info.plist` 或 JSON 元数据（例如 `package.json`）；XML 使用 `CFBundleShortVersionString`/`CFBundleVersion`，JSON 使用 `version`/`build`。不执行文件、不主动搜索安装位置，不支持二进制 plist。只有版本或 build 变化才触发候选，其他打包内容变化不算产品更新。

首次成功读取只保存基线。目录 watcher 监听选定文件的原子替换事件，经短暂防抖后检查；定期检查与宿主重启后的首次检查补足错失事件。文件暂缺、半写或解析失败会保留上次基线，恢复可读后继续比较。切换监测路径会建立新基线。候选标记 `sourceType: local-version`，链接只提供官方文档参考，不把本地观察冒充官方公告；完整本地路径不写进候选。

`updateResearchMode` 默认为 `notify`，只显示更新候选。用户切换为 `investigate` 后，新本地版本候选可触发受预算约束的调查任务；宿主忙碌时排队，重复候选不会重复建立调查。它不自动复刻所有功能，也不自动批准前台操作。实时触发依赖 DSH 宿主正在运行及操作系统文件事件；宿主退出、休眠或漏报时依靠下一次检查补偿，不承诺应用关闭后仍能即时触发。

当前 host 校验生成 tarball 的结构和摘要，不执行生成代码。行为、视觉和生命周期的隔离验收需要实际运行并由用户提交记录；agent 自述不能替代它。三项最新验收通过后，Host 自动进入 ready，并通过 DSH 的公开 installBundle 安装启用；研究工具本身不能直接修改 profile。默认关闭公开来源定期扫描，本地版本路径默认留空，自动调查默认关闭，子任务委派也默认关闭；启用委派前需要确认实际 provider 是可追踪的进程内 DSH 实现。

## 验收的含义

纯逻辑测试、打包检查、真实 DSH 接线、参考应用行为、视觉对照、安装/卸载恢复是不同证据。一个层次通过不会自动把其他层次设成通过。详见 [validation.md](validation.md) 和 [use-cases.md](use-cases.md)。这些文档描述验收合同；实际完成程度以本次运行输出和仓库验证记录为准。

## 独立功能插件与自动安装

每项复刻产物都是可移交的 npm tarball：独立包名、明确版本、编译入口和 DSH bundle patch。它不能替换 OpenCodex 或 DSH 官方包，不能依赖研究目录的绝对路径，也不能把 OpenCodex 作为运行时依赖。隔离验收环境不加载 OpenCodex，验证禁用/重启/再启用/卸载及状态恢复。

最后一项独立验收通过后，Host 复核当前规格、包摘要、证据和截图，自动进入 ready，停止研究会话，然后交给安装控制器。安装器只接收任务 ID，读取其已登记且匹配摘要的真实包，保存稳定副本，通过当前 profile 的 pluginManager.installBundle(path, {enabled:true}) 对应接口安装。包操作按 profile 串行，同任务重复请求合并。研究 agent 和来源内容不能指定任意安装 spec。

安装请求 ID、产物摘要、包名/版本、原生结果和日志路径写入任务。只有原生结果为 applied 或 restart-required，且目标和启用状态相符，才记 installed；后者明确需要重启，不声称正在运行。失败不会无限自动重试。重启后的未完成请求标为 interrupted；用户重试时先核对相同摘要的持久包源，已安装则走原生启用操作，不重复 pnpm 安装。

界面提供原生插件详情入口。启用、禁用、卸载和后续配置仍归 DSH 插件管理；研究记录保留当时的安装回执，不把历史回执当作用户后来手动调整后的实时状态。OpenCodex 卸载不删除已生成插件的依赖包。安装包持久副本不随研究文件清理而删除。
