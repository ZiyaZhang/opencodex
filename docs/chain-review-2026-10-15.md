# 0.2 链路复核与真实运行

复核日期：2026-10-15 UTC（本机 10 月 14 日）。测试宿主为公开 DSH `0.2.1-alpha.2`、Cordis `4.0.5-alpha.1`、Node `25.8.1`。这份记录区分产品实现、真实执行和仍未完成的验收。

## REA 对照

本轮读取 REA [`4692bb33300c7cb77b095b6cc0c33da861c1b860`](https://github.com/morluto/rea/tree/4692bb33300c7cb77b095b6cc0c33da861c1b860) 的 [reconstruction readiness](https://github.com/morluto/rea/blob/4692bb33300c7cb77b095b6cc0c33da861c1b860/docs/reconstruction-readiness.md) 与 [obligation ledgers](https://github.com/morluto/rea/blob/4692bb33300c7cb77b095b6cc0c33da861c1b860/docs/reconstruction-obligation-ledgers.md)，并复核入口 skill 的目标路由和留存视图方法。公开包当时为 `rea-agents@6.5.0`。本机 Node 25 不在该包声明的 Node 22/24/26 支持范围；本轮没有安装或运行 REA 引擎。

最有价值的架构约束是：静态材料只产生待验证的要求；每项要求需要对应实现、场景和有同等证明能力的验收结果。未知、跳过、缺少工具均不能折算为通过。REA 自己的 conformance runner 针对其内部 fixtures，不是可直接复用的通用 Codex UI 克隆验收器。

OpenCodex 采用这套证据和验收思路；DSH 包生成、预算、运行器及安装控制器仍由本项目实现。公开 SDK 已足够回答的问题直接读声明；只有目标确实涉及打包资源时才调用 REA，不能让所有任务先经过解包。

## 发现的问题与修复

| 问题 | 影响 | 0.2 的处理 |
| --- | --- | --- |
| Node 公共请求没有使用本机已配置的代理 | 官方源超时，真实候选一直未验证 | 尊重环境代理/macOS HTTPS 代理；实际官方扫描成功，原始响应留存。只作用于公共发现请求 |
| 只有候选文字，没有可靠的研究资料交接 | 模型重新抓取或读取整份 RSS | 原文 SHA-256、抓取时间与单项 JSON 摘录绑定；旧 ETag 无有效留存文件时重新抓取 |
| SDK 定位仍依赖通用提示词 | 模型重复读框架或猜路径 | `sdk` 返回实际版本、exports、有限声明与摘要；`.ts` 导入映射到真实 `.d.ts`；视图留存并复用证据 ID |
| 留存 SDK 正文是 JSON 长行 | 文件工具按行截断，模型又花调用解码原内容 | 留存改用保留真实换行的 Markdown 声明片段；原始版本、路径、偏移和摘要一并保存 |
| 恢复总是携带冗长会话 | 重复读材料，前期探索污染后续实现 | 默认仍原会话续跑；可显式选择新执行上下文，同任务、同目录、同预算，保留历史与指导 |
| 每轮把全部 UTF-8 字节当成 token | 大量相同上下文重复高估预留，过早暂停 | 同模型路线用已结算输入校准，加 25% 余量；变化内容逐字节保守预留。未知用量、总额与每日限制不变 |
| `verifying` 只有状态，没有自动执行者 | 包生成后不能进入真正的验收 | Host 验收控制器校验真实包，串行启动独立 DSH profile，留存运行身份、日志与回执 |
| 安装通过和功能通过容易混淆 | 用原生安装冒充复刻完成 | 原生生命周期与行为/视觉/状态恢复分开；适配器必须逐项覆盖规格 ID，视觉必须关联真实对照图 |
| 环境或验收器错误被当成代码错误 | 模型反复修不存在的功能缺陷 | 缺少运行环境、适配器或验收覆盖时阻塞；实际失败才进入受限修复 |
| 验收中断后重新调查 | 重复支出并丢失交接阶段 | 用同一规格和包摘要继续验收；中断保持 interrupted，不能生成成功回执 |

完整单项功能验收器仍是缺口。0.2 提供 `opencodexFeatureVerifier` 契约，**没有内置能够自动操作任意 DSH UI 的 CUA 适配器**。其注册存在也不证明场景覆盖。缺少该能力时自动流程会明确阻塞；仍可登记真实人工验收，但不得用合成记录把真实任务变绿。

## 已执行的检查

- 官方更新源通过生产 `scanSources` 实际抓取，解析出 14 个近期候选，错误为 0；主环境再通过 Host 的 scan/create/start 路径选择了 **Shared thread snapshots**。没有手工写入此候选。公告不等于本机已开放，日志扫描也不等于真实 Codex 升级触发已验证。
- 真实原生生命周期执行器使用已有 `dsh-opencodex-async-questions@0.1.0` 实验包，在独立 DSH_HOME 中完成 install、disable、enable、remove、removed 五阶段。重启后检查实际 fiber 激活/禁用与最终卸载，原生变更返回 applied；不加载 OpenCodex，不调用模型。这证明通用运行器接线，不证明新候选生成成功。
- `npm run check`：类型检查、180 项测试、构建通过。包含缺失验收器不能安装、规格覆盖不足不能通过、取消等待、重启恢复、上下文交接仍计费、SDK 路径与源文件防篡改。合成适配器仅用于自动化回归，不计入真实功能验收。
- 入口 skill 通过 `quick_validate.py`；资源目录、链接与有界读取由测试覆盖。未对“节省了多少 token”作受控比较结论。

## 同一真实候选的生成尝试

选中的是官方 2026-08-20 的 [Shared thread snapshots](https://learn.chatgpt.com/docs/changelog#codex-2026-08-20-app)：只读快照不会随原会话变化，涉及用户主动分享、脱敏后审阅、访问范围和撤销。

任务 ID：`27d07514-51d6-4a9e-9562-25b66d055978`。使用 DeepSeek-V4-Pro、推理 Off、单次输出上限 8,192；任务总上限始终为 400,000 tokens，最多两轮修复，没有续额。用量含缓存输入，不是费用金额。

1. 首段四次模型调用后，确认用量 79,456，无规格或产物，触发无进展暂停。记录显示模型读了整份 RSS 和通用手册，促成单项资料交接修复。
2. 同会话继续后累计 217,890。SDK 的 `.ts` 路径不兼容导致两次失败，仍无规格；该错误已加入实际声明链接回归。
3. 新上下文继续后累计 282,281，留存了 8 条来源/SDK 证据。下一请求要求 141,021 的预留而余额为 117,719，预算门限暂停。该样本促成按已结算输入校准的预留改进。

执行者提供了续跑指导并修改运行基础设施，因此本次属于**有人工介入的诊断实验**，不能作为无人干预的一键成功案例。功能代码必须由任务生成流程实际产出；不会把维护者另写的插件归到这次成功记录。

4. 校准预留后再次续跑，同一任务累计 **352,159 tokens / 16 次模型调用**，没有未知用量和未结算预留；仍无规格或插件产物，因连续四次调用未新增证据/规格暂停。记录显示模型读取了留存 SDK，但文件工具把 JSON 的声明字符串按单行截断，随后继续用 shell 解码；这导致留存正文改为真实换行的 Markdown。修复经过回归，**尚未用新的付费生成实验验证效果**。剩余 47,841 tokens 保留，没有抬高任务或每日额度。

因此本轮真实候选的结果是 **发现成功、研究部分完成、生成失败、未进入该任务的隔离验收和安装**。没有生成新的独立功能插件，也没有把旧提问插件的原生测试回执归到它名下。模型仍会在最小规格前过度读取；强制每阶段产出和更完整的功能验收适配器是后续关键工作，不能靠继续增加手册或额度宣布解决。

## 尚不能声称完成的部分

- 当前会话的 Codex 原生 UI 和本地预览访问受到工具限制，没有切换 CUA/CDP/浏览器通道绕过。没有新增 Codex 或 DSH 界面截图，也没有视觉通过记录。
- DSH CUA/REA 研究运行环境未实际跑通。已有资料及可选适配契约不等于安装和授权完成。
- 缺少完整的独立功能验收器。尤其云端账户、链接托管、工作区访问范围不能由一个本地 UI 包自动等价替代。
- 主任务是否到达生成包、自动验收和自动安装，以该任务真实回执为准。生命周期 fixture、绿色单测和 UI 可访问性不是它的替代证明。

本地完整响应、运行日志、会话和截图不进入公开包；公开报告只保留来源链接、方法、问题与结果摘要。
