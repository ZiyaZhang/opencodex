# 生成链路复核：为什么一直读 SDK

复核环境：公开 DSH 0.2.1-alpha.2、DeepSeek V4 Pro（reasoning off）。桌面版 DSH 已通过原生 UI 实际访问；它的应用版本为 0.2.0-rc.2，插件管理中未安装 OpenCodex。此前研究运行在另一个独立预览 profile，两者不能混作同一验收环境。

## 失败证据

真实更新候选 Shared thread snapshots 的任务消耗 352,159 token、16 次模型尝试，未保存规格、未产出功能包。这一失败记录保留。计数包含缓存输入，不等同于相同数量的全价新输入，也不能在缺少实际账单时换算金额。

留存日志显示：第一轮读取完整 RSS 后，单次输入由约 1.2 万涨至 2.7 万 token。后续声明路径出现 `.ts` / `.d.ts` 不匹配，JSON 中的长行被文件读取器截断，模型又调用 shell 解码。模型已经表达“信息足够”，却仍继续查询下一份声明。

这不是一个文件格式错误能独立解释的问题。

## 架构问题与修复

| 问题 | 影响 | 本轮处理 |
| --- | --- | --- |
| 新增证据等同于进展 | SDK 的每次读取都可能给循环续命 | 研究调用次数和费用直接从持久账本计算；SDK、任意证据、暂停或新上下文均不能重置 |
| 只有全任务预算 | 研究可以吞掉开发额度 | 研究/规格分配 25%，上限 10 万，最多六次请求；第一次未校准请求由总预算兜底，后续请求必须满足研究余额；未知用量仍占用预留 |
| 规格只是提示词中的建议 | 模型必须自行摸索工具协议、保存规格、切换阶段和搭项目 | 增加有结构化参数的 `opencodex_submit_plan`；规格与进入开发的状态转移原子保存，支持重复投递幂等 |
| 原始资料交给模型自行恢复 | 每次续跑重读 RSS、目录和旧证据 | Host 直接交接单项来源、证据 ID、最新规格与预算；用户要求单独留存为需求文档，不冒充运行观察 |
| 一开始暴露全部工具 | 不相关 schema 成为每轮输入；阶段切换也带来巨额保守预留 | 规划仅开放三个 OpenCodex 工具；完成后结束规划 turn，自动转入同一任务的新开发上下文；开发按需加载其他工具，已有权限限制仍生效 |
| 只有“参考手册”，没有适时交接 | 模型不断寻找应该读的章节 | 已有问题卡、补全、通信配方按目标匹配，开发交接只附一个有摘要哈希的短节；保留不确定性和真实 SDK 版本要求 |
| 验收依赖到最后才检查 | 无验收器也会花钱开发，然后必然卡住 | 默认自动运行在建会话前检查独立验收器和插件管理；选择人工验收后才允许生成待验收实验包 |
| 模板把 build 当 test | 只有编译通过也显示测试通过 | 模板的测试命令要求真实测试文件；缺少测试不再默认为成功 |
| 更新过滤只面向 UI | CLI/performance 中的运行时功能被漏掉 | 对压缩、检查点等具体运行时机制保留候选，并注明原始产品面；不推断其桌面可用性 |
| 调试源码与已安装包混淆 | 修改后复测仍可能运行旧代码 | 验证驱动先核对运行协议与实际工具，再允许启动模型；新包经 DSH profile 的原生安装路径生效 |

借鉴 REA 的重点是把证据、待完成要求和可比的验收结果分开，而不是只把它的说明文字加入 prompt。参考已核对的 [REA obligation ledger](https://github.com/morluto/rea/blob/4692bb33300c7cb77b095b6cc0c33da861c1b860/docs/reconstruction-obligation-ledgers.md) 和 [readiness conformance](https://github.com/morluto/rea/blob/4692bb33300c7cb77b095b6cc0c33da861c1b860/docs/reconstruction-readiness.md)。本轮未声称运行了 REA 引擎。

## 本轮生成回归

另用“普通问题卡与输入框并存”验证生成链路。它是用户提出的已有用例，不是真实更新候选的端到端成功，也不是对原失败用例的等难度成本比较。

本轮总验证上限 120,000 token。一次部署误跑使用了旧包，已停止；其 24,586 个已确认 token 与 22,954 个未结算预留全部计入上限，没有抹去。新任务因此只分配 72,460 token，旧失败候选的额度未增加。

新协议第一次模型调用就保存了规格和空插件骨架，实际 5,770 token（输入 5,198，输出 572）。随后的工具全集展开使保守预留达到 119,306，超过剩余额度，被阻止而没有发出请求。这直接暴露了工具分阶段加载和新上下文交接的必要性。

后续运行结果以当前账本、实际包和独立验收记录为准；没有登记包、真实运行和验收回执时，不标记链路完成。

## 仍需补齐

- 通用独立行为/视觉验收器仍未配置。生命周期 runner 可以确认安装、启停、重启和卸载，无法替代具体功能验收。
- UI 用例不能把用户要求或官方公告当作已观察的目标 UI。缺少 Codex 原图或实际 DSH 交互结果时，视觉/交互义务继续开放。
- 共享链接涉及服务端、访问控制与撤销；本地 HTML 导出不能默认为同等功能。应在方案中识别关键服务缺口。
- 运行时功能需要事件与并发状态证明，现有统一视觉必选 schema 尚需支持明确的适用性。异步压缩已加入专项研究指导，尚未生成或验收为功能插件。
- 规划成功只是一个里程碑；开发阶段仍可能失败或用尽预算。不得用更多 evidence、空规格、编译成功或合成验收记录掩盖这个结果。
