行为：

1. 先把 `tests/host.test.ts` 里的 `fixture()`、`fakeDsh()`、`fakeLlm()`、`fakeTimers()` 抽到 `tests/helpers/host-fixture.ts`，host 测试改为导入；给 fixture 的 `now` 加一个可以拨动的时钟（后面 T5 测缓存过期要用）。行为不变。
2. `appendCheckLog(directory, entry)` 往 `<directory>/checks.jsonl` 追加一行 JSON：`{ at, startedAt, trigger: 'startup'|'timer'|'manual'|'run-once', pid, window: { fromTag?, toTag? } | null, added: { releases, files, desktop, rss }, errors: string[], index?: { entries, commit } }`。单行、`\n` 结尾、追加后 fsync。文件超过 2 MB 时先把它改名为 `checks.1.jsonl`（覆盖旧的）再写。
3. `readLastCheckLog(directory)` 返回 `{ entry?: CheckLogEntry; problem?: string }`：最后一行解析出的对象；文件不存在时 entry 为空；最后一行损坏时往前找最近一条完整的，都坏时 entry 为空、problem 说明。只读文件尾部 64 KB。
4. `check()` 跑完（成功或整次失败）追加一行；`trigger` 由调用方传入：启动后首次为 startup，定时器为 timer，`check` 动作为 manual，T9 的 run-once 为 run-once。被锁拒绝的检查不写日志，也不改 `lastCheck`、`lastCheckAt`。
5. `src/core/lock.ts`：`acquireLock(directory, kind)`，`kind` 为 check 或 research。`lock.json` 内容 `{ pid, kind, startedAt, heartbeatAt, hostname }`。进程内按目录计数：本 pid 已持有时再拿任何种类都成功并加一，`release()` 减一，归零才删文件；只有别的 pid 持有才可能拒绝。别的 pid 持有且「心跳在 5 分钟内」且「`process.kill(pid, 0)` 不抛 ESRCH」时返回 `{ held: false, by: { pid, kind, startedAt } }`；心跳过期但 pid 还活着时，隔两个心跳周期（60 秒）复查一次，仍过期才接管；pid 不存在直接接管。接管：先把旧文件挪到唯一名并和当初读到的内容比对，不同就放回并按被拒处理，相同才改名为 `lock.stale.json`，再用临时文件加 link 新建（不支持硬链接的文件系统退回 `wx`），写完回读确认 pid 是自己，否则当作被别人抢先、返回 held:false。持有期间每 30 秒续写 heartbeatAt（定时器 unref）。损坏的 lock.json 当不存在处理。
6. `check()` 在 `joined` 的回调里拿 check 锁（所以本进程第二个检查请求仍然是加入正在跑的检查，不是被锁拒）。没拿到时抛 `LockedError`（继承 `ValidationError`，消息按 `by.kind`：`另一个 DSH 进程正在检查（pid N，开始于 <本机时区时间>）` 或 `…正在调研…`）。`src/host/index.ts`：定时器路径和 `check` 动作路径遇到 LockedError 都把下一次定时改到 10 分钟后（`checkAndRearm` 的 finally 里按错误类型区分）；`check` 动作路径让它以 `gateway/bad-request` 返回。
7. 快照新增：`lastCheckLog?: CheckLogEntry`（读文件的最后一行；读不出时 problem 进 notice）、`hostPid: number`、`lock?: { pid; kind; startedAt }`（只在别的活 pid 持有时给，判断方法同第 5 条，不接管）。页面（T7a）据 `lock` 提示并禁用「检查更新」，据 `hostPid` 判断上次检查是不是别的进程跑的。
8. 卸载时释放本进程持有的锁。

测试：追加和读取（含轮转、尾部损坏行、problem）；锁的创建、同进程重入计数、别的活 pid 持有时拒绝、心跳过期复查后接管、pid 不存在接管、接管回读失败、释放；host 测试：两次 check 前后串行、用假锁文件模拟另一进程时 check 被拒且不写日志、定时器改为 10 分钟、快照里的 lock 和 hostPid。

## T9 run-once 模式、launchd 脚本和文档

文件：`src/host/index.ts`（`Dependencies` 加 `runOnce?: boolean`，默认读 `process.env.OPENCODEX_RUN_ONCE === '1'`）、新建 `src/host/run-once.ts`（写 `last-run.json`）、新建 `launchd/opencodex-daily.sh`、`launchd/com.opencodex.daily.plist`、`package.json`（`files` 加 `launchd/`）、`README.md`（新节「无人值守」）；测试 `tests/host.test.ts`。

已核对的事实：两个 CLI 的 `--help` 只列启动器参数；`--no-open` 和 `--port` 写在 profile 后面传给 dsh-web-app（默认端口 3080），所以 `"$DSH_BIN" --profile "$DSH_PROFILE" --no-open --port 0` 成立。桌面端 CLI 在本进程里启动 profile，环境变量能传到插件；DSH 收到 SIGTERM 会正常卸载。

行为：

1. run-once：`open()` 后不等 60 秒，立刻跑一次 check（trigger run-once），接着 `await` 自动调研队列的 `idle()`，然后写 `<directory>/last-run.json`：`{ startedAt, finishedAt, pid, check: <checks.jsonl 那一行或 null>, reports: <队列的 results>, notice? }`，并记一条 info 日志 `opencodex: run-once finished`。之后不再定时。锁被占时也写 last-run.json（check 为 null、notice 说明）。
2. `launchd/opencodex-daily.sh`：可配环境变量 `DSH_BIN`（默认 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`）、`DSH_PROFILE`（默认 `opencodex`）、`OPENCODEX_TIMEOUT_MIN`（默认 120）、`DSH_HOME`（默认 `$HOME/.dsh`）。流程：记下 `last-run.json` 当前 mtime；`OPENCODEX_RUN_ONCE=1 "$DSH_BIN" --profile "$DSH_PROFILE" --no-open --port 0 &` 取 `DSH_PID`，再 `caffeinate -i -w "$DSH_PID" &`；每 20 秒看一次 mtime，变了就对 `DSH_PID` 发 SIGTERM，等 60 秒还在就 SIGKILL；超过时限同样结束；日志由脚本自己写到 `$DSH_HOME/opencodex/logs/daily-YYYY-MM-DD.log`（保留 30 天）；退出码 0 完成、2 超时、3 启动失败。
3. `launchd/com.opencodex.daily.plist`：Label `com.opencodex.daily`，ProgramArguments `/bin/bash` 加脚本的绝对路径占位符，StartCalendarInterval 08:00，RunAtLoad false，EnvironmentVariables 含 `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin`，StandardOutPath / StandardErrorPath 写绝对路径占位符（launchd 不展开 `~` 和变量）。
4. README「无人值守」：把脚本复制到 `~/.dsh/opencodex/bin/`（插件卸载或升级不影响任务），plist 复制到 `~/Library/LaunchAgents/` 并把占位符换成绝对路径，`launchctl bootstrap gui/$(id -u) …`，手动触发一次（`launchctl kickstart -k gui/$(id -u)/com.opencodex.daily`），卸载，看日志，和桌面应用同时运行时锁的行为，电脑睡着时的行为（launchd 唤醒后补跑；`caffeinate -i` 挡不住合盖睡眠）。launchd 下读不到 `~/.zshrc`，脚本不依赖它。
5. 验证：用验证环境（临时 DSH_HOME）跑脚本一遍，交付说明里贴日志和 `last-run.json`。不要对 `~/.dsh` 跑。

测试：run-once 下首次检查不等 60 秒、等队列、写出 last-run.json、不再定时；锁被占时的 last-run.json；run-once 由 Dependencies 控制，测试不改 `process.env`。

提交：`feat: run-once mode and a launchd job for unattended daily checks`
