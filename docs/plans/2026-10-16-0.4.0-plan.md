# OpenCodex 0.4.0 实施计划

设计见 [2026-10-16-0.4.0-design.md](2026-10-16-0.4.0-design.md)。一个任务一个实现者，每个任务先写失败的测试再实现，`npm run check`（Node 24）通过后提交；每个任务提交后过两道评审（对照任务文本的范围评审、代码质量评审），有问题由同一个实现者修到评审通过再进下一个任务。提交信息用英文祈使句，作者 ZiyaZhang，不加任何 Co-Authored-By。

基线：分支 `v2`，提交 1df0d00（0.3.1）。工作树 `~/harness/opencodex-v2`。测试在 `tests/*.test.ts`，用 `tsx --test`；现有的 host 测试用 `tests/helpers/` 里的假服务，照着写。

通用约束：

- 不动状态机、不加信息源、不改数据目录的已有文件格式（只增字段、增文件）。
- 第三方文本（PR 正文、RSS、文案、报告正文）在每个提示词里都要声明是数据不是指令，现有写法保留。
- 新界面文字用设计文档「用词与状态」里的词；不自造简称。
- 每个任务只改自己列出的文件；要改别的文件先在交付说明里讲清楚原因。

## T1 检查日志与数据目录锁

文件：新建 `src/core/run-log.ts`、`src/core/lock.ts`；改 `src/host/actions/check.ts`、`src/host/actions/context.ts`（HostContext 加字段）、`src/host/index.ts`（触发方式）、`src/host/actions/snapshot.ts`、`src/host/remote.ts`；测试新建 `tests/run-log.test.ts`、`tests/lock.test.ts`，改 `tests/host.test.ts`。

行为：

1. `appendCheckLog(directory, entry)` 往 `<directory>/checks.jsonl` 追加一行 JSON：`{ at, startedAt, trigger: 'startup'|'timer'|'manual'|'run-once', pid, window: { fromTag?, toTag? } | null, added: { releases, files, desktop, rss }, errors: string[], index?: { entries, commit } }`。单行、`\n` 结尾、追加后 fsync。文件超过 2 MB 时先把它改名为 `checks.1.jsonl`（覆盖旧的）再写。
2. `readLastCheckLog(directory)` 返回最后一行解析出的对象；文件不存在返回 undefined；最后一行损坏时往前找最近一条完整的，都坏返回 undefined 并在返回值外提供错误信息（函数签名自定，snapshot 要能把问题放进 notice）。只读文件尾部 64 KB。
3. `check()` 结束（成功或整次失败）都追加一行；`trigger` 由调用方传入：启动后首次为 startup，定时器为 timer，`check` 动作为 manual，T9 的 run-once 为 run-once。
4. 快照新增 `lastCheckLog?: CheckLogEntry`。页面（T7）以它为准显示「上次检查」；本进程的 `lastCheck` 保留不动。
5. `src/core/lock.ts`：`acquireLock(directory, kind)`，`kind` 为 check 或 research。`lock.json` 内容 `{ pid, kind, startedAt, heartbeatAt, hostname }`，用 `wx` 创建；已存在时读出，持有者满足「心跳在 5 分钟内」且「`process.kill(pid, 0)` 不抛 ESRCH」就返回 `{ held: false, by: {...} }`，否则覆盖接管。拿到后每 30 秒续写 heartbeatAt（定时器 unref），`release()` 在 pid 是自己时删除文件。损坏的 lock.json 当不存在处理。
6. `check()` 开始前拿 check 锁；没拿到时不跑采集，抛出 `LockedError`（消息：`另一个 DSH 进程正在检查（pid N，开始于 <本机时区时间>）`）。`src/host/index.ts` 里定时器路径捕获 LockedError 后把 `lastCheck` 记为带这一条 `check:` 错误行的失败结果，并把下一次定时改到 10 分钟后；`check` 动作路径让它作为 `gateway/bad-request` 返回给页面。
7. HostContext 增加 `lock` 相关句柄的存放位置由实现者定，但卸载时必须释放持有的锁。

测试：追加和读取（含轮转、尾部损坏行）；锁的创建、被活进程持有时拒绝、心跳过期接管、pid 不存在接管、释放；host 测试里两次 check 一前一后、以及用假锁文件模拟另一进程时 check 被拒绝且定时器改为 10 分钟。

提交：`feat: persist a check log and serialize checks across processes with a data-directory lock`

## T4 自动调研队列

文件：`src/core/settings.ts`（`autoResearch`）、`src/core/candidate.ts`（`research?: { autoAttemptedAt?: string; lastError?: string }`）、`src/host/remote.ts`（设置字段表、快照 `researchQueue`）、新建 `src/host/actions/research-queue.ts`、改 `src/host/actions/check.ts`、`src/host/actions/classify.ts`、`src/host/actions/context.ts`、`src/host/index.ts`（卸载时停队列）、`src/host/actions/snapshot.ts`；测试新建 `tests/research-queue.test.ts`，改 `tests/host.test.ts`、`tests/candidate.test.ts`。

行为：

1. 设置 `autoResearch: 'off' | 'high' | 'medium'`，默认 `high`，校验只接受这三个值。
2. `enqueueResearch(ctx)`：在 `check()` 的分类步骤之后、以及 `classify` 动作之后调用。挑选：status 为 new；`classification.relevance` 为 high（设置为 medium 时 high 或 medium）；没有 `mergedInto`；`research.autoAttemptedAt` 不是今天（UTC 日期）；`dshMirrorPath` 非空。排序：相关度高在前，再 createdAt 倒序。已在队列或正在跑的不重复加入。
3. 队列由 `ctx` 上的一个 worker 顺序消费：每条先 patch `research.autoAttemptedAt = now`，再调用现有 `report(ctx, id)`。`report` 因每日上限拒绝（识别 `admit` 抛出的错误类型，必要时给它一个可识别的 Error 子类）时清空队列并记 notice：`今天的报告额度用完，还有 N 条明天继续`。其他失败 patch `research.lastError`（裁到 300 码点）后继续下一条。`ctx.signal` 中止时停止。
4. 消费前拿 research 锁（T1 的锁，种类 research），没拿到时清空队列并记 notice `另一个 DSH 进程正在调研（pid N）`；跑完释放。
5. 快照新增 `researchQueue: string[]`（排队中的 id，按顺序）和 `researchNotice?: string`（上一条队列级提示）。现有 `busy.candidates[id] === 'report'` 继续表示正在跑。
6. 手动 `report` 动作不受队列影响；它和队列对同一条候选的互斥由现有 `exclusive` 保证。

测试：挑选规则每一条；顺序；每日上限时停止并提示；失败后继续并记 lastError；锁被占时跳过；信号中止；快照字段。

提交：`feat: queue automatic research for high-relevance candidates after each check`

2. `launchd/opencodex-daily.sh`：可配环境变量 `DSH_BIN`（默认 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`）、`DSH_PROFILE`（默认 `opencodex`）、`OPENCODEX_TIMEOUT_MIN`（默认 120）、`DSH_HOME`（默认 `~/.dsh`）。流程：记下 `last-run.json` 当前 mtime；`caffeinate -i` 包着 `OPENCODEX_RUN_ONCE=1 "$DSH_BIN" --profile "$DSH_PROFILE" --no-open`（无头启动参数以该 CLI 的 `--help` 为准，实现者核对）；每 20 秒看一次 mtime，变了就 SIGTERM，等 60 秒还在就 SIGKILL；超过时限同样结束；日志写 `$DSH_HOME/opencodex/logs/daily-YYYY-MM-DD.log`（保留 30 天）；退出码 0 完成、2 超时、3 启动失败。
3. `launchd/com.opencodex.daily.plist`：Label `com.opencodex.daily`，ProgramArguments 指向脚本，StartCalendarInterval 08:00，RunAtLoad false，EnvironmentVariables 含 `PATH=/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin`，StandardOutPath / StandardErrorPath 指向上面的日志目录。脚本路径写成占位符，README 里说明要换成安装后的绝对路径（`node_modules/dsh-opencodex/launchd/…`）。
4. README「无人值守」：安装（复制 plist 到 `~/Library/LaunchAgents/`、`launchctl bootstrap gui/$(id -u) …`）、手动触发一次（`launchctl kickstart`）、卸载、看日志、和桌面应用同时运行时锁的行为、电脑睡着时的行为。
