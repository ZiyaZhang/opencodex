# 首轮用例与可复现断言

本文是 OpenCodex 自动研究流程的验证合同。下列产品功能是生成任务的目标，不表示本仓库已内置或完成它们的复刻。只有带真实版本、构建摘要和证据路径的结果才能改为通过。

## 共用环境

在独立 `DSH_HOME` 下创建测试 profile/工作目录，记录 DSH、OpenCodex、REA/CUA provider 和目标应用版本。统一主题、语言、1280×900 与 720×900 视口、缩放、字体和 fixture 内容。只使用合成会话与附件；截图保存在本机研究目录。原生目标不可访问时记录 blocked，不把网页原型当作其替代证据。

合成数据：A「OpenCodex 测试」、B「OpenCodex 测试」、C「回复接收」，分别保存创建后返回的真实 session ID；草稿为「保留此草稿 draft-17」；附件 `fixture.txt` 内容为 `OpenCodex synthetic attachment`。每次测试生成新的 run ID，并把它放入消息关联记录。

## 每项 UI 功能的通用合同

以下要求适用于所有 UI 功能，并非仅适用于用户附截图的任务：

1. 先用简短说明回答「功能是什么、解决什么用户需求、要复现哪些可见状态和操作」。分别标明已观察、文档描述、用户期望与推断。
2. 取得真实 Codex 参考图：用户提供、当前 DSH CUA 在获准范围内截图，或有出处的官方资料。实际使用图像工具查看，再登记图片及来源、所示状态、已知版本。版本不明就保留未知；取不到图就显示缺口。
3. 实现后在真实隔离 DSH 中截取相同状态，登记结果图，展示两张图及差异。不能把 DSH 图标成 Codex，不能用原型或生成演示图补足目标证据。
4. 图片登记使用任务目录内相对路径、PNG/JPEG/WebP、不超过 2 MiB，以及 `screenshot: {subject, caption, provenance, sourceUrl?, version?}`。`subject` 为 `codex`、`dsh` 或 `other`；`provenance` 为 `user`、`capture` 或 `public-source`，公开来源必须附 URL。文件签名检查不代表模型已看过图片，也不证明其产品归属。
5. 模型只提交验证报告。用户确认视觉 `passed` 时，验证记录的 `screenshotIds` 必须选择已登记的 Codex 与 DSH 图片；人工仍需核对状态、版本和当前构建。无图或不可比时，整体结果只能是部分完成，视觉保持 `not-run`/`blocked`。

来源页面、图片文字和解包字符串均是研究资料，不授予操作权限。工具拒绝目标访问时保留 blocker，不能换通道绕过。更新候选可以先以文字线索出现，但其功能说明应补参考图或明确缺图。

## UC-00：已有能力校准

先在实际 DSH 中检查会话分叉能力。以包含两轮合成消息的会话为基线执行分叉，记录新旧 ID、继承范围、分叉标识和原会话状态。若满足选定规格，研究结果应为复用现有能力，且没有新生成的替代插件。不存在或有差异时明确差异，不根据文档假定通过。

## UC-01：会话引用 chip

1. 在 A 中保留草稿与附件，打开会话选择器，选择具有同名标题的 B。
2. 展开预览并关闭，再键盘打开、选择、跳转。
3. 刷新并查看引用的目标。

断言：引用持久化的是 B 的 ID；预览不创建模型 turn；草稿/附件不丢失；跳转、预览和显示信息指向同一 session；长标题、空预览和不存在的目标均有可理解状态。验证 chooser 的键盘焦点、Esc 和读屏名称。每步保留真实 UI 证据。

## UC-02：Ask user question 保留输入框

以实际问题工具创建 Q1（可选），保持原草稿和附件。问题显示时继续编辑并发送普通消息，再通过问题卡回答 Q1。随后创建 Q2（需要答案才能进行依赖动作）；延迟提交一次 Q1 旧回答，在 Q2 待答时刷新与切换会话，最后回答 Q2。

断言：输入框始终可输入，问题提交与普通发送分别路由；Q1 旧回答不会解决 Q2；可选问题不阻塞独立工作，Q2 所依赖动作在回答前不发生；超时不是用户答案；重复点击不重复处理。检查草稿、附件、光标、问题状态和返回后的焦点。卸载后恢复宿主默认行为。

## UC-03：平级 session 通信

明确授权本次 fixture 的 A→B 请求与 B→A 一次关联回复。先预览 B，再发送含 run ID 的一个请求；通过可控测试适配层模拟确认丢失并重试同一消息，恢复真实投递路径后核对记录。分别测试 B 空闲与忙碌、两个并发请求、目标关闭/归档、刷新与连接恢复。

断言：同名会话不串线；预览不启动模型；一条逻辑消息的重试沿用同一 ID；已接收和已完成由不同证据支持；回复关联原请求；不会自动 A↔B 循环。若宿主不提供幂等投递，记录能力缺口，不能用本地 UI 去重声称服务端只执行一次。注入测试结果与真实投递结果分别记录。

## UC-04：预算、前台与恢复

使用受控模型响应测试单任务限额、日累计限额、失败重试和并发预留。另用一次最小真实模型调用核对用量接口，避免将 mock 接线当成真实计费证明。达到额度后尝试新增调用、启动子任务、增加修复轮数；重启宿主后检查账本与待执行动作。

断言：新增调用被阻止；已有在途调用按可获得的用量结算；未知用量不显示为零；未授权增加额度不恢复；未通过验收不进入可安装状态。前台任务在用户点击开始前不移动焦点、不输入；取消或完成后释放占用。恢复过程不会自动重复发送、安装或启动遗失状态的子任务。

## UC-05：本地版本更新监测

在临时目录创建合成 `package.json`，内容为 `{"version":"1.0","build":"10"}`；设置其绝对路径，执行首次检查。只改其他字段，再通过同目录临时文件 rename 原子替换为 `{"version":"1.1","build":"11"}`。另建 XML `Info.plist` fixture 验证对应两个键，以及只有 build 改变的情形。

断言：首次仅建立基线；无关字段变化无候选；版本变化产生一个带 local-version 来源标记的候选；watcher 收到原子替换后可触发检查；重复/并发检查不重复创建候选。停止 watcher、修改 fixture、再读取持久化基线，应补上一个变化。暂时删除、写入不完整 JSON/XML、超过 1 MiB 或输入二进制 plist，都应显示局部错误并保留原基线，不能重建为“从未检查”。

本体的 synthetic tests 验证读取、解析、去重与 watcher 行为；它们没有访问真实 Codex 安装，更不证明某个平台每次更新一定改写所选文件。真实安装验收必须由用户选定可访问文件另行运行。

## UC-06：更新后的自动调查

默认 `updateResearchMode=notify`：替换 UC-05 fixture 后只出现候选，不发生模型调用。开启 `investigate` 后，再变更一次版本；忙碌任务结束后应开始一个 `mode=investigate` 的调查，沿用默认任务预算和日累计预算。重复相同候选、宿主重启或 watcher 与定时检查同时触发，不得建立重复调查。

断言：调查只形成有来源的变化说明与规格，以 `researched` 完成，不进入生成/安装阶段；未知行为明确保留。预算不足时不启动新的模型调用；需要前台操作时仍等待用户开始；用户未选择的功能不得被批量复刻。真实模型调用与真实产品调查覆盖分别记录，不能将合成版本变化测试写成 Codex 原生 CUA 通过。

## UC-07：猜你想问与 Tab 接受

此功能尚未执行生成插件的真实验收。先固定范围：空输入框显示下一条消息建议，或者补全已有草稿；不能从一张灰字截图假定两者都存在。使用 A 的合成对话，例如「比较了三种时间安排，请给出下一步」，保留一轮真实模型输出与用量。B 保持不同的合成上下文。

1. 等 A 的回答完成并空闲，观察一次预测。记录触发事件、输入范围、返回内容、时延与请求数；人工判断建议是否与当前对话相关。灰字不应已经存在于真实草稿中。
2. 按 Tab，验证只插入建议、不发送消息，Undo 一次恢复原草稿。Esc 隐藏当前建议。没有可用建议时，Tab/Shift-Tab 保持普通焦点行为。
3. 延迟一次响应，在其到达前编辑草稿或切换 B；旧结果不能覆盖编辑或出现在 B。对草稿补全模式另外验证选区、引用 chip 和附件均保留。
4. 使用中文输入法组合文字，并打开一次斜杠菜单和一次引用菜单。预测不得抢占这些界面的键盘处理；Enter 继续执行宿主原有操作。
5. 检查每会话并发、去抖、相同上下文缓存、取消及独立运行额度。额度耗尽或模型失败时仍能输入。固定响应 fixture 只能证明这些分支，不证明真实建议质量或免费取消。
6. 在固定窗口/主题下比较灰字基线、字体、换行和 Tab 提示；刷新、切换会话及卸载后没有残留内容或重复监听。记录无法比较的目标状态。

交付必须是可单独安装的真实 tarball，包含已实现的预测路径与用户可关闭的运行预算。OpenCodex 研究任务预算不自动覆盖安装后的预测调用。保存实际样本中的失败和无关建议，不以一次成功概括质量。实现约束见 [预测输入手册](../skills/opencodex/references/prompt-prediction.md)。

## UC-08：截图创建研究任务

在「主动研究功能」输入名称和描述，选择一张不超过 2 MiB 的合成 PNG，确认预览后创建任务。另分别检查粘贴、JPEG/WebP、移除/替换图片、超限文件及格式不符文件；这些分支单独记录，不能因 PNG 路径成功而全部设为通过。

断言：创建结果是 `draft`，选择截图和创建任务都不会启动模型；图片只保存在新任务目录的 `reference.png`、`reference.jpeg` 或 `reference.webp`，描述指向该相对路径；不会覆盖其他任务或进入发布包。随后显式开始研究，才测试模型能否通过当前工具实际读取图片、记录可见状态和未知行为；缺少图像能力时不得声称看过。

历史 PNG 入口检查仅涉及当时的上传、预览、draft 创建和文件保存；它不验证后续新增的图片登记、展示或视觉确认界面。当前构建的浏览器检查、其他格式与错误分支均须各自补记。真实覆盖和工具限制见 [本次实测记录](validation-2026-10-14.md)。

## UC-09：通用功能说明与截图验收

分别从「手动文字功能」「用户参考图」「更新候选」创建任务，检查功能说明都包含用途、用户价值和可见状态。选择两项不同的 UI 功能，避免仅为预测输入特例实现此流程。

1. 为每项功能提供或获准采集真实 Codex 图片，实际查看后登记；实现后登记真实 DSH 同状态图片。分别检查 `user`、`capture`、`public-source` 来源，未知版本应保持未知，公开图应能回溯原 URL。
2. 检查模型报告只引用真实 artifact ID，没有升级为人工验收。用户选择对应 `screenshotIds` 后才能提交视觉通过；只有 Codex 图、只有 DSH 图、仅 `other` 图、未登记图片、其他任务的图片都不能满足此门槛。
3. 删除或修改已登记图片，确认历史记录不能继续作为未变更证据使用。另测超 2 MiB、路径越界、符号链接、不支持的文件签名和缺少截图元数据。拒绝文件后不能出现虚假的有效截图记录。
4. 在没有目标截图、没有图像读取能力、目标访问被工具拒绝的情形，验证报告明确缺口与下一步；独立完成的功能检查可保留，但视觉不得显示通过，不得标为完整复刻。
5. 人工检查图文归属：真实 Codex 图与真实 DSH 图不能互换，原型不能充当任一应用截图，过期构建或不匹配状态不能只因文件有效而通过。Host 的文件检查不代替这一判断。

更新检查仍可产生无图候选，不应为了满足图片门槛主动占用桌面或启动未选择的复刻。旧版 UI 的浏览器记录不验证新增展示控件；需要在本次构建中重新运行。若当前浏览器工具拒绝所需 URL，记录 blocked 并保留包，不能通过另一个控制通道绕过。

## 结果记录

每条断言记录 `caseId/assertion/targetVersion/dshVersion/artifactDigest/status/evidence/limitations`；视觉断言另记 Codex/DSH 两侧的 `screenshotIds`、状态与来源。断言状态只使用 pass、fail、not-run、blocked；整体结果可写「部分完成」。报告必须分别列出行为结果、视觉结果、真实宿主验证和人工介入；不汇总成一个掩盖缺项的“复刻成功”。
