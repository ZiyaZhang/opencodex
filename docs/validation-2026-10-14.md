# 0.1 预览版实测记录

执行日期：2026-10-14。DSH 为公开 npm `0.2.1-alpha.2`，Cordis 为 `4.0.5-alpha.1`。开发机器使用 Node `25.8.1`；README 推荐 Node 24 LTS。下面区分已执行结果和仍待验证的能力。

## OpenCodex 本体

- 在独立 `DSH_HOME` 中安装真实打包产物，DSH 侧栏、研究/发现/资料/设置页面均可操作。模型调查使用 DSH 自身的 SessionController、Tools 与 LlmRuntime。
- 用户提供的 PNG 通过真实页面上传、预览并创建任务，保存为任务目录下的 `reference.png`。创建本身没有调用模型；参考图没有进入仓库或分发包。
- 合成版本文件从 `1.0.0` 原子更新到 `1.1.0` 后，文件监听自动创建候选卡，无需点击检查，也没有调用模型。自动调查保持关闭。本次没有读取实际 Codex 安装目录。
- 实际模型请求记入账本；暂停和续额保留已有会话与资料。一次恢复从保存的规格进入开发阶段，没有要求重新创建规格。
- 连续四次模型尝试未登记证据/规格的暂停门槛已在真实任务中触发。保守预留也实际触发过提前暂停，界面显示原因，用户可以看到进度后续额。
- 最终 `npm run check` 的类型检查、106 项测试和构建通过。覆盖并发预留、缓存用量、provider 重试、未知用量、重启、前台许可、自动调查去重、包检查、图片路径与模板生成。另有 3 项隔离验收驱动器守卫测试，以及实验插件的 5 项编译产物测试通过。

## 生成实验的失败与人工协助

最初的“提问时保留普通输入框”实验消耗 **1,723,815 tokens**，包括缓存输入、输出和多次恢复；前段使用 DeepSeek-V4-Flash，后段切换 DeepSeek-V4-Pro。它只形成证据、规格和部分文件，没有产出可安装插件，按失败样本保留。

这暴露了反复读取框架、工具返回重复完整任务历史、暂停后重走阶段的问题。随后增加了无进展暂停、精简工具返回、恢复阶段，以及经过独立构建检查的通用 DSH 插件模板。模板只含空的 slot contribution、Host stub 和构建配置，不含目标功能代码。

第二次实验使用 DeepSeek-V4-Pro 和该模板，消耗 **1,099,185 tokens / 24 次模型尝试** 后暂停。执行者通过恢复说明要求复用公开接口，并反馈了 CSS 选择器遗漏中间节点的问题；模型完成了功能代码和构建入口修改。中途发现 High 推理耗尽单次 4,096 token 上限而未写出代码，测试会话改为 Off 后开始产生文件。

模型停止后，维护者把生成源码复制到 `examples/async-questions`，修正一处 Cordis effect 无 DOM 分支的 TypeScript 返回值，补写说明和 5 项编译产物测试，然后构建打包。样例是**有人工指导、人工完成构建修复的实验产物**，不能描述为无人干预的一键成功。原始生成代码和用量记录保留在本机；公开样例不带原始聊天。

样例的类型检查、编译、包结构、marker 的会话/提问类型判断和 effect 清理测试通过。它使用 DSH 已有问题卡和普通输入框，没有第二套问答服务。测试使用明确的组件契约替身，不能证明真实浏览器的布局、发送、附件和迟到回答已经通过。

另一个来源读取冒烟任务消耗 34,160 tokens。上述两次生成及冒烟合计 **2,857,160 tokens**，包含缓存输入；这不是账单金额，也不包含开发 OpenCodex 本身的助手开销。失败尝试保留在总数中，不能用最终几个成功调用代替整体成本。

## 隔离验收方法

生成产物使用另一个独立 `DSH_HOME` 验收，避免研究环境与输出插件共用依赖树。测试驱动器只提供本地确定性的 tool call；实际执行 DSH 的 agent loop、`ask_user_question`、问答服务、SessionController 和真实网页。验收过程不调用外部模型。

安装输出插件前的对照已确认：普通问题卡出现时原生输入框不可见，回答后原有草稿恢复。该对照并不证明插件已经改变行为。

后续测试还需要记录普通提问、普通消息排队、草稿与附件、迟到回答、会话隔离、刷新以及卸载。确定性驱动器可验证服务接线与 UI 行为，不能验证通用模型质量。此前对照的 UI 操作为外部验收者完成，不能算成研究任务已经自主具备 CUA。可复现驱动和操作步骤位于 `tests/fixtures/output-qa`。

本轮恢复后，浏览器工具拒绝访问本地页面并明确禁止换通道绕过，因此**生成样例的真实界面验收未完成**。重启服务及带认证的 HTTP 200 仅证明链接恢复，不算界面验收。

## 通用截图能力

根据用户补充的产品要求，研究详情加入 Codex 参考与 DSH 实现两栏，可查看已登记截图、说明、来源、版本和其他研究图；旧版任务上传的参考文件仍可查看。图片按需读取，不放进每次状态轮询。

新截图记录需要元数据，视觉通过必须显式关联同一任务的 Codex 与 DSH 截图。Host 检查文件格式边界、大小与登记摘要；最终视觉判断仍需要人确认图像归属和可比状态。缺图或图片变化不能取得新的视觉通过记录。

后端路径隔离、摘要与大小校验，以及组件的图片选择、缺失状态、异常和跨任务请求取消均已做自动化测试。新增双栏界面，以及后续的字体、间距和统一 Phosphor 图标改版（用户反馈字号偏小后，正文/任务标题调整为 14px，辅助文字至少 12px），仍受上述浏览器工具限制，**未完成真实浏览器验收**。先前 PNG 创建入口测试不替代新增界面测试。

## REA 对照后新增的执行改进

长资料的模型读取接口改为默认章节/来源索引，短于 3,000 字符的资料仍一次返回全文；显式读取最多 6,000 字符。界面资料阅读保持全文。当前 DSH 适配手册正文 12,171 字符，默认索引响应 763 字符；这仅是返回内容的字符量比较，不是模型 token、费用或生成成功率对照。

同一会话恢复时不再重复注入完整入口 skill，任务约束仍保留，最新预算与证据通过 status/record 获取。新模板直接支持 JSX，scaffold 回执包含实际入口源码、模板依赖与文件摘要、构建命令和输出位置。通过新的独立目录执行 npm ci、加入最小 JSX contribution 后构建和打包通过，无需修改构建入口。这是模板接线测试，不是目标功能验收。

对照方法、REA 实际机制和未实现的版本化 API map 见 [REA 学习记录](rea-learning.md)。本轮没有再启动大额度模型生成循环，也不据此宣称端到端成本下降。

## 未覆盖

- “猜你想问”真实建议质量、平级会话通信的完整生成和验收。当前有研究手册和用例合同，不是已经交付的复刻功能。
- 任意更新自动生成插件、跨平台全面兼容、DSH 关闭时的系统级唤醒。

公开报告只保留合成测试结果与摘要。原始模型日志、任务状态、个人截图和临时认证信息留在本机。

## 0.1.2 交付接线修复

任务列表现在按需读取真实参考缩略图并显示是否有插件包。详情增加已登记包的分片下载，Host 每次检查同任务路径、文件链接、包结构和 SHA-256，Client 在全部分片到齐后再校验完整摘要。实验包不会因可下载而取得验收通过或自动安装。既有任务可上传多张截图并说明可见状态，保持原任务状态和预算。

本机既有的“猜你想问”用户图片已补登记。第二次提问实验的公开包已关联回原研究任务，标明模型代码经过人工指导与一处编译修复，保持暂停、零项通过验收。安装前的 DSH 截图仅登记为基线研究图，不标成 Codex 参考或插件实现效果。实际图片和实验包通过新的读取/分片接口校验，图片 95,691 bytes，实验包 4,275 bytes，包 SHA-256 为 `2d72b9db747e7ff1d3bcc71d0ca2a0e3b31b15a4bb0f12229402b98f19458a81`。

更新发现改为逐功能解析官方 RSS/HTML；首次扫描、去重、旧基线迁移、失败不推进 checkpoint、候选批量选择不启动模型均有自动化回归。官方 `.md` 旧地址已失效。本机对新官方源的真实请求仍超时，不能宣称自动网络巡检通过。当前预览中的 6 项候选是维护者另行读取官方页面后手工整理并明确标注来源的记录，没有伪造成功扫描或修改其 checkpoint。

本轮没有再启动付费模型生成。新版图片布局、下载按钮和批量选择尚未取得真实浏览器验收；组件测试、构建和服务健康检查不替代该结论。

## v0.1.3 自动安装流程

验收完成后由 Host 自动调用当前 profile 的公开 `pluginManager.installBundle`，不再要求下载后手动导入。最后一项独立验收触发安装；研究 agent 自述仍不能制造通过结果。安装回执记录包名、版本、产物 SHA-256、请求 ID、原生结果及日志，界面提供原生插件管理入口。失败与中断不循环重试。

本次用公开 DSH 0.2.1-alpha.2 和真实产物 `dsh-opencodex-async-questions@0.1.0` 跑了五个独立进程阶段：自动安装并启用、重启后 active 并禁用、重启后禁用状态保留并重新启用、重启后 active 并卸载、再次重启确认包和条目不存在。四项原生变更均返回 applied；每阶段均通过。该 DSH_HOME 没有安装 OpenCodex，也没有创建模型会话或外部模型调用。运行方法见 [native installation fixture](../tests/fixtures/plugin-install/README.md)。

安装测试使用合成的验收记录作为控制器输入，只证明安装接线、持久化和 Host 生命周期，不证明功能视觉验收。用户此前确认“问题卡与普通输入框同时可用”；草稿、附件、迟到回答和完整视觉对照仍按实际证据逐项验收。未把现有 paused 研究任务改成通过或自动部署。浏览器工具仍拒绝实际页面访问，本轮没有新增 UI 截图或声称完成页面视觉检查。

本次 `npm run check` 通过类型检查、166 项测试和构建。新增回归覆盖最后一项验收触发安装、重复请求、失败不循环、中断恢复、确切包源复用、包名冲突、缺失原生服务、退出取消，以及界面的重启提示和原生管理导航。
