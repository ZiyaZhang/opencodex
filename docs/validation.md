# 验证合同

此文档定义 OpenCodex 本体和生成插件的验收范围，不把未来测试计划写成已完成结果。实际执行日期、版本、命令输出和截图必须单独记录；缺少证据的项目保持 not-run。

## 本体必须验证

| 范围 | 可接受的证据 | 无法替代它的证据 |
| --- | --- | --- |
| 截图任务入口 | 真实浏览器中选择/预览/创建 draft、本地文件及不启动模型的记录 | 只通过图片解码单元测试 |
| 本地版本监测 | 合成 XML/JSON 基线、原子替换事件、重启补查、暂缺恢复、重复抑制 | 仅发现文件存在或比较包内容 hash |
| 自动调查 | notify 模式不启动模型、investigate 模式去重排队、预算门槛、researched 完成 | 候选状态标签或 mock 模型成功 |
| 资源加载 | 清单中每个 ID 可读，路径均在包内，引用目标存在 | 仅检查 Markdown 标题 |
| 预算 | 并发预留、结算、失败、重启及日累计边界的可重复测试 | 单次总 token 数 |
| DSH 模型接线 | 真实模型请求和宿主用量记录对应 | mock provider 测试 |
| 任务生命周期 | 创建、暂停、取消、重启恢复及修复上限 | 单纯显示状态标签 |
| 前台队列 | 未开始时无桌面动作，开始后仅执行约定步骤，完成释放 | 截图按钮可点击 |
| 包装/加载 | 分发包在声明版本的 DSH 中安装、注册、卸载 | 编译成功或 HTTP 200 |
| 安装门槛 | agent 自述无法跳过 Host 校验；验收通过后自动调用原生安装 | 提示词说“需要审核” |

资源测试应验证机器可读合同与文件引用，运行时测试应验证行为；不为文案措辞写脆弱快照。链接检查必须区分内容已读取、HTTP 可达和离线未知。

当前截图入口的真实浏览器验证已覆盖 PNG 上传、预览、创建 draft 和在该任务目录保存 `reference.png`。没有启动该 draft 的模型，也没有发布图片；此结果只确认入口 UI 接线。图像实际读取、其他上传分支，以及「猜你想问 / Tab 接受」生成插件的行为和视觉验收仍需分别执行，不能由入口通过推导。详细边界见 [UC-07 / UC-08](use-cases.md)。

## 生成插件必须验证

按照 [use-cases.md](use-cases.md) 创建合成数据和独立 profile。固定目标版本、候选包 digest、viewport、主题与测试数据。逐条保存行为与视觉结果；用户要求视觉细节时，缺少参考截图不能标记视觉通过。

安装生成代码时，为验收单独设置研究工作目录内的 `DSH_HOME`，再在其中创建测试 profile。仅改变 `--profile` 不能隔离同一个 DSH_HOME 下共享的插件依赖目录。记录测试 DSH_HOME、启动工作目录和端口，但公开报告只使用占位符或相对路径；不要复制日常凭据文件、会话目录或私有配置进入可发布包。真实模型测试仍按所使用宿主的实际用量记录，不能把独立测试进程当作绕开研究预算的通道。

真实流程至少覆盖：首次安装、第一次使用、关键交互、相关失败和取消、刷新/重启、会话隔离、卸载恢复。对模型驱动行为保留输入、输出和可用的用量记录，同时注明样本范围。单次成功不代表所有问题或所有版本均正确。

## 报告模板

每次运行记录：

- 本次验证的提交/包摘要与 DSH/目标/CUA/REA 版本。
- 命令与真实 UI 场景，以及 pass/fail/not-run/blocked 数量。
- 行为差异、视觉差异、宿主能力缺口和未知项。
- 本地证据相对路径；公开交付只包含合成数据和可公开摘要。
- 人工修改或协助，以及生成流程是否独立完成。
- 首次尝试和恢复/重试各自的 token、持续时间、是否形成证据/规格/代码/可安装包；读完大量源码但没有产物的尝试也计入成本与失败样本。

研究 agent 的 verification 是报告入口，不是可信验收章。Host 的静态包检查只证明已检查的包装约束，也不能自动证明功能、安全性或真实 UI 质量。产物区应展示这些证据的实际覆盖范围；全部验收通过后自动安装，无额外安装确认。

发布前重新构建并检查**最终 tarball**的实际文件清单与内容，不以源码目录或较早构建代替。只分发原始源码的构建产物、skills、公共来源索引和公开文档；确认不含研究状态、会话、凭据、个人截图、目标应用解包产物及本机绝对路径。公开仓库提交清单和 npm tarball 清单分别检查：npm 的 `files` 不会限制 Git 提交范围。

## v0.1 交付边界

v0.1 的知识包和任务流程不代表已完成任意 Codex 功能的全自动复刻。本次未凭本文件认证 Codex 原生应用的 CUA 可用性，也未认证自动视觉对照通过。需要在用户可访问的目标、已注册的 DSH CUA provider 和独立测试环境中运行上述场景，再逐项记录结果。本地监测当前支持 XML plist 与 JSON，不支持二进制 plist；本次自动化测试只使用临时目录中的合成元数据，没有读取实际 Codex 安装。

监测的“即时”指宿主运行期间收到文件事件后尽快检查，仍包含操作系统事件延迟和防抖时间；不能用它承诺毫秒级响应、休眠期间检测或宿主退出后运行。重启补查与周期检查负责补足错失事件。开启自动调查仍受模型预算和前台使用选择约束，调查完成为 researched，不代表生成插件可安装。
