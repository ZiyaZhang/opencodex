# Budget, interruption and resume

Read the authoritative job status before a new phase and after resuming. Do not maintain a competing token counter in prose. The host ledger decides whether another model request can start; actual provider usage may arrive after a call finishes.

The job budget includes research, generation, retries, repair attempts and tracked child agents. Account limits also aggregate concurrent jobs. OpenCodex v0.1 uses UTC settlement dates for daily accounting; unresolved reservations carry across midnight. Confirmed tokens and reservations/in-flight usage are different quantities; neither a rough estimate nor a screenshot of one request is a complete ledger. Failed calls may incur usage, and a provider that omits usage creates uncertainty rather than zero cost.

Only use in-process DSH child tasks whose parent lineage is tracked by OpenCodex. Do not launch an external model CLI, direct model API process, or untracked worker to continue after a limit. Ordinary compiler/test subprocesses are distinct, but must have bounded duration and cannot conceal model calls.

Checkpoint at useful boundaries: target fingerprint, evidence IDs/digests, answered and unresolved questions, specification revision, working files, tests completed, pending side effects and next operation. Never replay a send, install or other mutation solely because the previous response was lost. Reconcile its recorded identity or report an uncertain outcome first.

Checkpoint before expensive calls. On a budget/time/repair limit, stop starting model work and retain the last saved result. A paused host may reject further tool calls as well as model calls; do not try to bypass that gate merely to write another checkpoint. The durable job state and existing files are the resume point. An exhausted limit requires the user to raise that limit; a resume action does not replenish it. On cancel, stop owned work and retain useful artifacts. On restart, release or conservatively account unresolved reservations according to the host's recovery policy; do not pretend an in-flight call completed without evidence.

After an explicit resume from paused/blocked/failed, a valid saved same-job specification lets the Host restore the previous `specifying` or `building` phase. Read `status` and selected dossier records, preserve their IDs, and continue the existing project. Do not send a transition into the stage the Host already restored. Without a valid specification, work resumes in `researching`. Automatic restoration of `verifying` and automatic repair are not implemented: inspect the saved outcome and identify the remaining acceptance/repair step instead of claiming it resumed. Budgets and prior elapsed usage persist across all these paths.

During `researching`, the Host separately pauses before a fifth model attempt without new evidence/specification registered through the job tool. Failed/retried attempts count, and writing a file alone does not reset this progress counter. An explicit user resume resets the counter while preserving the pause reason; it does not increase the token budget. Building/verifying are exempt, but entering those phases requires the corresponding genuine work and specification. The entry skill's three focused reads and roughly 25% initial-research allocation are planning guidance, distinct from this enforced gate. Do not manufacture findings or change stages to avoid a pause.

Foreground waiting is a separate paused state. Request the concrete target/actions and await user start; revalidate focus and target version after waiting. Finish or cancel the foreground lease promptly when done.
